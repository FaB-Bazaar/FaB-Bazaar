# Volzar Chat UI

## Rendering rules

- **Every card list renders through `CardTable`** (VolzarChat.tsx) — binder/wants (flat `tableRows`), deck drills / hero kits / comparisons / archetype consensus (`tableSections`), and AI search results. New card-shaped results must emit CardRow rows, not text lines. Columns are adaptive (only rendered when some row has data); a tail note column (`CardRow.note`) gets its header via `QuickActionResult.tableNoteHeader` (e.g. "Decks", "Owned").
- **Table thumbnails need `max-w-none`** — the global `img{max-width:100%}` reset lets auto table layout collapse the `w-9` image cell to 0-width whenever a sibling column demands `w-full`. Symptom: images "never load" but their naturalWidth is fine.
- **Model markdown** gets `{p}/{d}/{r}/{h}/{i}` glyphs + literal `<br>` → line break via `rehypeRuleGlyphs` (rule-glyphs.ts). rehype-raw is deliberately OFF — raw HTML renders as text unless that plugin converts it.
- **Pitch notation `(p1)`/`(p2)`/`(p3)` in model markdown → colored pip dots** (1 red / 2 yellow / 3 blue; count + color double-encode per SC 1.4.1) via the same plugin (`pitchicon` element). CSS dots, NOT `/icons/pitch-N.png` — those card-frame pips are red at every pitch and unreadable at text size. The system prompt (app/api/volzar/prompt.ts) steers the model to write `(pN)` after card names. Pinned in rule-glyphs.test.ts + `e2e/volzar-pitch-pips.spec.ts` (stubbed SSE, no AI spend).

## Card hover tags (linkify)

- Card names in replies hover-link ONLY if a tool's STRUCTURED payload carried them: `harvestCardsFromStructured` reads `results[].printings`, top-level `cards[]`, and `deck.*` (and threads `tcgplayer_url` into previews — the rail's affiliate buy link). The MCP server route must place the payload in `structuredContent` — spreading `...result` into the JSON-RPC result is NOT enough (the browser bridge reads only `structuredContent`). `get_results` is the reference: it emits `cards[]` (name + printing_id + image_url).
- **Linkify must fold exotic spaces** — gpt-oss writes card names with U+202F (narrow no-break space) in markdown tables; it renders identically to a space but silently defeats name matching, so linkify looked randomly broken run-to-run. `normalizeForMatch` (card-linkify.ts) folds NBSP/NNBSP/en-em-thin spaces length-preservingly. If linkify "sometimes doesn't work," check codepoints before debugging React.

## Behaviors

- Auto-scroll keys on `items[]` — anything that grows a card IN PLACE (e.g. the matchup panel) needs its own scroll effect (see the matchupPanels effect).
- **Chat-first workspace: wide chat is the DEFAULT** — opening any workspace item leaves the panel a narrow reference rail (`setPaneFocus('chat')` in the `workspaceUid` effect) and DOM-focuses the composer (desktop-only `matchMedia lg`; skipped when mid-typing in another field). Deck work happens FROM the chat; clicking into the panel expands it. **No expand→contract flash**: paneFocus's useState default must stay `'chat'` (a 'workspace' default paints one wide frame before the effect contracts it) and the aside's engage-capture skips `[data-drill]` links (else a drill click expands the panel for the fetch's duration, then snaps back). Pinned in `e2e/volzar-workspace-minimal.spec.ts` + `e2e/volzar-workspace-focus.spec.ts` (gitignored; the flash test uses a delayed `page.route`).
- **Deck drills DEFAULT to `WorkspaceStrips`** (`workspaceView` state; `deckPublicId` + image rows → tiles, binders/comparisons → table since their rows carry the ±/quick-add actions; header Table2/LayoutGrid button toggles). Tiles reuse the DECK PAGE's treatment: 63/53 stacked crop (top 81% name bar + art, bottom sliver stats bar) + ×qty badge, sections split by pitch via `splitSectionsByPitch` (unit-tested) into deck-page style "Maindeck — Red/Yellow/Blue" colored headers; the table keeps source order. Hovering a tile floats a full-card detail overlay (`strip-hover-card`: image, type, collector · foil, prices) centered over the CHAT column — inside it on purpose so it never occludes the tiles being hovered — `pointer-events-none` so hover tracking doesn't flicker. **Clicking a tile (editable decks, non-hero) opens the tile ACTION MENU** (`tile-action-menu`: add/remove copy via `adjustQty`, delete all copies, move to library/inventory/bench, swap printing — deck-page parity) instead of engaging the panel: the aside's paneFocus capture handlers skip `[data-strip-tile]` targets. Move/delete re-drill via `refreshItemsForTarget` + refetch ownership. Tiles carry a green/amber/red collection-ownership dot (`fetchDeckOwnership` → inventory-comparison, best-effort). Section titles are pitch-split, so ALL deck category resolution goes through `deckCategoryFromSection` ("Maindeck — Red" → maindeck, "Bench" → benched — blind lowercasing broke both); strip sections carry `sourceTitle` for optimistic row matching. The drill now includes a Bench section (else move-to-bench looks like deletion).
- **Deck cards self-describe on open** — an instant 📊 `deckShapeSummary` line (df.describe-style: qty-weighted type buckets + cost curve, also appended to the AI context) next to the 🎨 color line, plus deck-scoped AI launcher chips (`DECK_AI_PROMPTS`: Describe this deck / What else fits? / Discuss matchups, and for OWN decks "Review latest Talishar game" — `fetchLatestGameForDeck` instant lookup → `analyzeGame`, banner when no games) that `sendTurn` a one-message question; deck contents already ride the pending-context queue. Button placement rules: "Add to my decks" ONLY on non-editable decks (copying your own deck is nonsense); "Add card" lives in the workspace panel HEADER (right cluster with the view toggle + close — exactly one `ml-auto` wrapper, or the header splits), not on the chat card. **The context must stay self-sufficient** — chips make ZERO tool calls, so context lines carry `(pN, cost N, <type line>)` per card and the Hero line appends its rules text; without those the model invents card roles (Sink Below-as-attack incident).
- Instant pickers (Decks to beat / archetype / kit) are mutually exclusive and close when their action runs — keep new pickers consistent. **They render TWICE**: a desktop Popover anchored to the rail button (`hidden lg:block` content) + a `lg:hidden` inline panel (the ⚡ sheet's deep links need an in-page panel on phones, where the popover anchor is display:none) — both fed by shared `renderXPicker()` fns. e2e must scope picker content to `getByRole('dialog')` (the popover) or hit strict-mode duplicates.
- **My decks has a + split button** → the site's `CreateDeckDialog`; the submit handler resolves the hero printing (dialog passes `heroCardUniqueId` only), `decksClient.createDeck`, dispatches `deckCreated` (navbar), bumps the rail count, and drills the new deck open. Throwing keeps the dialog open on failure.
- **The rail is stateful** — data launchers carry live count badges (`rail-count-{binders,wants,decks}`; binders from `binderOptions`, wants = `wantsList.cards.length` (the route has no total and ignores limit), decks = `/api/decks` filtered `!isSystemDeck && !featured` client-side — `/api/decks/basic` 404s, don't use `getUserDecksBasic`). The launcher whose content is open in the workspace gets `aria-current` + a left-border highlight: drills PUSH onto `workspaceStack`, so provenance = `workspaceStack[0].sourceAction` (set in `runInstant` for non-drill actionIds; `refreshDataItem` preserves it via its `...item` spread).
- `fetchToBeatHeroes` PAGINATES: `/api/decks/community` clamps limit to 50/page and the featured pool is 100+, so a single page silently drops heroes from the dropdown.
- Matchup swap-row thumbnails come from the deck card's `tableSections` via `buildSwapLookup` — the deck drill must keep its Inventory section or side-in enrichment silently degrades to name-only rows.
- **Server-side writes must refresh open tables** — CardSearchDialog adds AND successful AI write tools (`WRITE_TOOLS`) re-drill affected sources: dialog adds refresh their known target, AI writes refresh every on-screen mutable item (`collectMutationTargets`, deduped) since tool results don't say which binder/deck they hit. Fresh content swaps into matching items via uid-preserving `refreshDataItem`; a seq guard drops out-of-order responses. Without this, writes look like no-ops. The row ±/swap buttons instead update optimistically in place; a removal (− at qty 1, styled as trash) arms a 10s Undo bar that re-adds and refetches.
- **Add-card split buttons** (My binders tri-button: truncated target-binder-name segment picks via dropdown, + adds to it; My wants plus) and the deck drill's "Add card" footer button open the shared `CardSearchDialog`. Deck adds infer category from card types (hero/equipment/weapon → that slot, else maindeck) and are gated by `deckEditable` (= the deck GET's `canEdit`), so the button never shows on Decks to Beat / others' decks. The dialog closes itself in the SAME tick as `onSelectCard`, so added-card labels are recorded optimistically before the POST resolves; `flushAddDialog` folds them into one data card + one pending-context entry on close. Runners (`addSearchSelectionToBinder`/`...ToWants`) pass `forTrade` through verbatim — no `?? true` coercion.
- **Volzar is standard for all signed-in users** (2026-07) — the only gate left is signed-in vs signed-out. Logged out → inline `<AccessGate/>` with a "Sign in to chat" CTA (`/auth/login?callbackUrl=%2Fvolzar`). Do NOT restore the old signed-out `redirect()` — anonymous crawlers (Discord/Twitter embeds) must get a 200 with the OG tags from `layout.tsx`, and a 307 hides them behind the login page's metadata. Rate limits (the actual cost control): 50 msgs/user/day + 2,000/day site-wide + 30/hr burst, enforced in `/api/volzar` (policy in `lib/ai/tiers.ts`; superadmins exempt). Invariants pinned in `page.test.tsx` + `e2e/volzar-ux-fixes.spec.ts` (gitignored).
- **Cookie banner inset** — the fixed consent banner sits exactly over the composer (the shell ends where the legal footer starts). VolzarChat measures `[data-cookie-banner]` (attr lives in `components/cookie/cookie-consent-banner.tsx`) and pads the shell until consent is given. Don't remove the attr.
- **Prefer SQL-backed aggregate tools over inference** — "which Decks to Beat could I build?" = `compare_collection_to_decks_to_beat`; "how are my decks performing?" = `get_deck_performance`. Both are single deterministic calls (service SQL → `/api/decks/coverage` + `/api/results/performance`, `allowOAuth`), in `HOSTED_EXTRA_TOOLS` and steered in `prompt.ts`. When a suggested prompt needs decklist×binder or W/L math, add an aggregate tool — never let the model fetch lists and count. Coverage is printing-agnostic (`matchBy: 'card'`), same semantics as the deck-compare drill.
- **Comparison rows have in-row quick-add** — Missing/Partial rows carry `addQty` (needed − owned) which renders heart (wants) / folder (binder, `forTrade: false`) buttons in a tail "Add" column; handlers in VolzarChat (`quickAddRow`) write the shortage and re-drill the comparison via `compareRefresh` so the row migrates out of Missing. Actions live ON the row deliberately: the preview-rail buttons force mouse travel that hover-previews every card en route. `refreshDataItem` must copy `compareRefresh` or refreshes orphan the buttons.
- **Coverage rows are clickable** — the compare tool's MCP dispatch emits `structuredContent.coverageDecks`; `parseCoverageLines` (quick-actions) turns them into `CardLine`s with `deck-compare` drills rendered under the tool chip, so clicking a deck opens the existing You-vs-deck missing-cards comparison instantly (no AI). New interactive tool payloads should follow this pattern: structuredContent → pure parse fn (unit-tested) → existing drill/table machinery.
- **Session flags self-heal on open** — Volzar visibility (navbar item, homepage redirect, /opt "Ask Volzar") reads the login-time JWT `roles`, which goes stale when access is granted mid-session. VolzarChat calls `updateSession({})` once when the token fails `canUseVolzar` — the `{}` is REQUIRED: next-auth v5's `update()` with no args is a plain GET and never fires the jwt callback's `trigger === 'update'` DB re-read. Any client gate on Volzar access must pass ALL THREE flags to `canUseVolzar` (the /opt link shipped dropping `volzarAccess`, hiding it from manually-granted users).
- **Bridge B params are one-shot** — VolzarChat strips `?from=opt&…` via `history.replaceState` on mount so a reload can't resurrect a stale handoff.
- **Mobile shell height reserves ONLY navbar + tab bar** (7.5rem + 1px); the legal footer is a deliberate soft floor BELOW the fold — scrolling past the thread reveals it. Root layout column is min-h-**dvh**, not -screen: 100vh ≠ 100dvh on iOS and the mismatch renders as a dead band above the footer. Invariants pinned in `e2e/volzar-ux-fixes.spec.ts` (gitignored).
- **Empty-state prompts are server-built** (`lib/ai/volzar-suggestions` via page.tsx — personalized from binders/decks/wants/recent results; static fallback on any failure). VolzarChat may import ONLY the `SuggestedPrompt` type from that module — a value import pulls the `@/lib/services` barrel into the client bundle.
- **No header band (2026-07)** — the old title/model/New-chat row is gone; the thread + workspace get the full page height. New chat, the superadmin model picker, and the usage badge live at the TOP of the left instant rail (outside the `hidden sm:` chips group — phones still need New chat). A chips-above-composer variant was tried and reverted (`a23e449`/revert) — the user prefers the left rail; don't re-fold it without asking.
- **Instant strip is hidden < sm** (the tab bar's ⚡ sheet covers those actions on phones) but the PICKERS must stay renderable at every width — the sheet's "Decks to beat" deep link opens one in-page. The preview rail renders only once `hasPreviewableContent` (empty-state.ts) is true. Empty state order: greeting → suggested prompts → ⚡ explainer → composer (input BELOW the prompt cards); everything docks on the first turn. e2e pane-width assertions must measure `role=log`, not the composer textarea (Send shares its row).
- **⚡ mobile tab deep links** — Volzar-access users' bottom tab bar (`components/navbar/MobileTabBar`) swaps Search for an "Instant" sheet whose items link to `/volzar?action=<id>`; VolzarChat auto-runs the action and strips the param (one-shot, like Bridge B). The consuming effect is keyed on `useSearchParams`, NOT mount — tapping a sheet item while already on `/volzar` is a same-page navigation that never remounts the component (the original mount-only version shipped this bug). The id allowlist + href builder live in `instant-link.ts` — add new deep-linkable actions THERE (unknown strings never auto-run). `to-beat` opens the picker rather than running. Pinned in `e2e/volzar-instant-tab.spec.ts` (gitignored).
- "Swap printing" in the rail reuses the deck page's `ViewPrintingsDialog`, which fetches by `card_unique_id` — resolve it from the previewed `printingId` via `/api/search/core?printingId=` first. Preview-only/ephemeral: it swaps the rail's in-memory preview and writes nothing. Do NOT wire `/api/decks/[deckId]/printings/swap` — that persists a deck copy; chat has none.
