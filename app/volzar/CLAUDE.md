# Volzar Chat UI

## Core philosophy

- **Mobile-first, always** (owner-stated core principle, 2026-07-15): Volzar is primarily used on phones — at a physical game table, at armories, between rounds. Design every surface for a 390px viewport FIRST; desktop gets "greater things" (workspace rail, hover previews) as progressive enhancement. Concretely: no side-by-side column layouts as the only view of information, no hover-only affordances for anything essential, compact absolute answers over verbose deltas (see the matchup pile check).

## Rendering rules

- **Every card list renders through `CardTable`** (VolzarChat.tsx) — binder/wants (flat `tableRows`), deck drills / hero kits / comparisons / archetype consensus (`tableSections`), and AI search results. New card-shaped results must emit CardRow rows, not text lines. **Binder drills in the CHAT column default to a 2-per-row grid of BINDER-PAGE style tiles** (`BinderTileGrid.tsx`, testid `chat-binder-tiles` — mirrors `components/binder/BinderCard`: full image, name, collector/edition, type, Market/High/Mid/Low block, TCG purchase link, rarity gem + foil pill → printing swap, For Trade switch, −/qty/+ · printing link · trash; user request 2026-07-14). Rows carry `priceLow/Mid/High/Market`, `rarity`, `edition` (`toCardRow`). Trash = `removeRowEntirely` (whole inventory row, arms the same Undo bar); the switch = `setRowForTrade` + pure `setItemRowForTrade` optimistic flip. A header icon toggles to the CardTable (`chatCardView` keyed by item uid). Wants/comparisons keep the table default (their earlier user requests). Card-image click = the tile action menu, same as the table's thumbnail. Pinned in `e2e/volzar-binder-chat-tiles.spec.ts` (stubbed binder APIs). Columns are adaptive (only rendered when some row has data); a tail note column (`CardRow.note`) gets its header via `QuickActionResult.tableNoteHeader` (e.g. "Decks", "Owned").
- **CardTable must FIT its container, never clip** — card names `break-words` (not nowrap) and the type column carries `[overflow-wrap:anywhere]` to drop its min-content floor; wrapper is `overflow-x-auto` as a last resort. Without these the narrow workspace panel clipped the Foil/swap columns off the edge.
- **Table thumbnails need `max-w-none`** — the global `img{max-width:100%}` reset lets auto table layout collapse the `w-9` image cell to 0-width whenever a sibling column demands `w-full`. Symptom: images "never load" but their naturalWidth is fine.
- **Model markdown** gets `{p}/{d}/{r}/{h}/{i}` glyphs + literal `<br>` → line break via `rehypeRuleGlyphs` (rule-glyphs.ts). rehype-raw is deliberately OFF — raw HTML renders as text unless that plugin converts it.
- **Pitch notation `(p1)`/`(p2)`/`(p3)` in model markdown → colored pip dots** (1 red / 2 yellow / 3 blue; count + color double-encode per SC 1.4.1) via the same plugin (`pitchicon` element). CSS dots, NOT `/icons/pitch-N.png` — those card-frame pips are red at every pitch and unreadable at text size. The system prompt (app/api/volzar/prompt.ts) steers the model to write `(pN)` after card names. Pinned in rule-glyphs.test.ts + `e2e/volzar-pitch-pips.spec.ts` (stubbed SSE, no AI spend).

## Card hover tags (linkify)

- **AI search results default to the TILE view** (`search-tiles`, same `WorkspaceStrips` tiles as decks, one flat unsplit section) with a per-result Table2/LayoutGrid toggle (`searchResultView` keyed by tool-call id) back to the striped detail table.
- Card names in replies hover-link ONLY if the session card index knows them — fed by BOTH tool structured payloads AND instant-drill data items (`harvestCardsFromDataItem` pulls table rows; without it, tool-free deck-context answers had zero hover targets — the model needs no special tagging, linkify matches plain names). Tool side: `harvestCardsFromStructured` reads `results[].printings`, top-level `cards[]`, and `deck.*` (and threads `tcgplayer_url` into previews — the rail's affiliate buy link). The MCP server route must place the payload in `structuredContent` — spreading `...result` into the JSON-RPC result is NOT enough (the browser bridge reads only `structuredContent`). `get_results` is the reference: it emits `cards[]` (name + printing_id + image_url).
- **Linkify must fold exotic spaces** — gpt-oss writes card names with U+202F (narrow no-break space) in markdown tables; it renders identically to a space but silently defeats name matching, so linkify looked randomly broken run-to-run. `normalizeForMatch` (card-linkify.ts) folds NBSP/NNBSP/en-em-thin spaces length-preservingly. If linkify "sometimes doesn't work," check codepoints before debugging React.

## Behaviors

- Auto-scroll keys on `items[]` — anything that grows a card IN PLACE (e.g. the matchup panel) needs its own scroll effect (see the matchupPanels effect).
- **The workspace panel is a CONSTANT-WIDTH reference rail** (`flex-[0.8]` vs the chat's flex-1) — focus-follows-engagement width was tried and REMOVED by explicit user request (2026-07-11): no click anywhere resizes it, ever. Opening a workspace item DOM-focuses the composer (desktop-only `matchMedia lg`; skipped when mid-typing in another field) — deck work happens FROM the chat. `data-strip-tile`/`data-drill` attrs remain as e2e selectors. Pinned in `e2e/volzar-workspace-minimal.spec.ts` + `e2e/volzar-workspace-focus.spec.ts` (gitignored; the no-flash test uses a delayed `page.route`).
- **Deck drills DEFAULT to `WorkspaceStrips`** (`workspaceView` state; `deckPublicId` + image rows → tiles, binders/comparisons → table since their rows carry the ±/quick-add actions; header Table2/LayoutGrid button toggles). Tiles reuse the DECK PAGE's treatment: 63/53 stacked crop (top 81% name bar + art, bottom sliver stats bar) + ×qty badge, sections split by pitch via `splitSectionsByPitch` (unit-tested) into deck-page style "Maindeck — Red/Yellow/Blue" colored headers; the table keeps source order. Hovering a tile fills the LARGE `CardPreviewPanel` in the left rail's dead space under the launchers (the centered `strip-hover-card` floating overlay was tried and REMOVED once the rail preview landed — don't reintroduce it) (`rail-preview`, image capped `max-h-[32dvh]`, persists after unhover so add/swap stay reachable) — this replaced the old cramped panel-foot strip. The panel's actions are ONE compact 3-icon row (swap · wants · binder; binder target = the rail's to: picker — the in-panel binder Select was removed); rail image capped `max-h-[24dvh]` + tight paddings so the FULL panel fits above the fold at 100% zoom on laptop heights (was 32dvh — clipped); `CardTable`'s Qty header/cells center when ± editing is on (right-aligned, the label floated over the + button). **Clicking a tile (editable decks, non-hero) opens the tile ACTION MENU** (`tile-action-menu`: add/remove copy via `adjustQty`, delete all copies, move to library/inventory/bench, swap printing — deck-page parity) instead of engaging the panel: the aside's paneFocus capture handlers skip `[data-strip-tile]` targets. Move/delete re-drill via `refreshItemsForTarget` + refetch ownership. Tiles carry a green/amber/red collection-ownership dot (`fetchDeckOwnership` → inventory-comparison, best-effort). Section titles are pitch-split, so ALL deck category resolution goes through `deckCategoryFromSection` ("Maindeck — Red" → maindeck, "Bench" → benched — blind lowercasing broke both); strip sections carry `sourceTitle` for optimistic row matching. The drill now includes a Bench section (else move-to-bench looks like deletion).
- **Deck cards self-describe on open** — instant structured stat chips (`DeckStatsChips` from `result.deckStats`: color pips + a block-value histogram pill (defense 0/1/2/3/4+, present values only) + a combined AR·DR reactions pill + qty-weighted type buckets + cost curve, testid `deck-stats`). Community feedback 2026-07-15: reactions are SPLIT out of the buckets (attack vs defense reaction serve different purposes; "… Defense Reaction - Trap" must not bucket as "Trap"), and every Evo type line ("… Equipment - Evo Base Arms") folds into ONE "Evo" bucket instead of one per zone. NB "N Block" as a type bucket is real data — Block is a card type — distinct from the histogram pill. The dashboard also gets a ⚔ **Table setup** section (`TableSetup`, testid `table-setup` — replaced a one-chip "70 in library · cut 10" that read as a riddle; community ask 2026-07-15): three pre-game lines — **On the table** (hero + equipment-section split into equipment/weapons/off-hands via type line), **Shuffle up** (target of library count), **Back in the box** (cuts + spare gear). Library = maindeck + inventory qty MINUS plain gear — but Equipment/Weapon rows that are ALSO Action/Instant (Teklovossen Evos, "Mechanologist **Action** Equipment - …") shuffle into the deck and DO count (verified against the real Teklosaucen list: 76 − 6 plain gear = 70, not the naive 43); target 60, or 40 for Blitz/Commoner/Clash; the same sentence rides the AI context so "what stays out of the deckbox?" answers from data (`deckStats.library` + `deckStats.gear` from `deckTableSetup`) rendered on the chat card AND above the workspace card grid; the 🎨/📊 emoji strings still exist but are **AI-context-only** (`deckShapeSummary`/color line — the run-on text read badly in the card, 2026-07-14). `refreshDataItem` must copy `deckStats` or re-drills drop the chips. **Mobile deck bodies default to the pitch-split TILE view** (`chat-deck-tiles`, same `WorkspaceStrips`+`splitSectionsByPitch` as the workspace; header toggle → table, button `lg:hidden` for decks since desktop bodies live in the workspace; comparisons stay tables — quick-add is table-only). `CardLinesList` columns key off VISIBLE line count (hideTableLines used to leave 3 notes split across 2 columns). Pinned in `e2e/volzar-deck-chat-card.spec.ts` (stubbed deck APIs). Plus deck-scoped AI launcher chips (`DECK_AI_PROMPTS`: Describe this deck / What else fits? / Discuss matchups, and for OWN decks "Review latest Talishar game" — `fetchLatestGameForDeck` instant lookup → `analyzeGame`, banner when no games) that `sendTurn` a one-message question; deck contents already ride the pending-context queue. Button placement rules: "Add to my decks" ONLY on non-editable decks (copying your own deck is nonsense); "Add card" lives in the workspace panel HEADER (right cluster with the view toggle + close — exactly one `ml-auto` wrapper, or the header splits), not on the chat card. **The chat deck card is a contextual DASHBOARD** (2026-07-14, after a one-day workspace-toolbar detour that was superseded the same day): `DashLabel` sections — 📊 **Snapshot** (stat chips + section counts + Viewing), ⚡ **Actions** (`renderDeckActions`: Check what I own (`result.compareDrill` — replaced the lines drill-link; `refreshDataItem` must copy it) / View as cards / Add to my decks / View matchups / AI chips / Review latest), 💡 **Insights** (`deckInsightLines`, unit-tested: ownership coverage from the SAME `deckOwnership` map the tiles' dots use (only while that deck is docked) + Talishar record & strong/weak matchups from `deckPerf` — a `Map` filled by the rail's one `/api/results/performance` fetch; section hides when empty). The workspace stays a pure card list (chips above grid only). Actions render at every breakpoint — do NOT re-add a workspace toolbar without asking. **The context must stay self-sufficient** — chips make ZERO tool calls, so context lines carry `(pN, cost N, <type line>)` per card and the Hero line appends its rules text; without those the model invents card roles (Sink Below-as-attack incident).
- **Matchup panel = the ABSOLUTE inventory pile, NOT a delta** (community ask 2026-07-15): `InventoryCheck` (testid `inventory-check`) lists what the physical inventory pile must hold after siding — `inventoryAfterSiding(tableSections, sideboard)` in `deck-matchups.ts` (unit-tested): Inventory-section rows − side-ins + side-outs, counts clamped at 0. Rationale: coming off a previous round the deck's state is unknown, so a delta ("No removals") reads as "nothing to do" when last round's swaps may still be shuffled in — counting the pile against the list is the only stateless check. Renders in the NO-SWAPS case too (that's the case that prompted it). The **Side in / Side out columns were REMOVED same day** (owner: Talishar auto-sides from the plan, so the panel exists for the physical table on a phone — don't re-add the 2-col delta grid; the in/out lists still ride the AI context via `matchupsToContext`). Pinned in `e2e/volzar-matchups.spec.ts`.
- Instant pickers (Decks to beat / archetype / kit) are mutually exclusive and close when their action runs — keep new pickers consistent. **They render TWICE**: a desktop Popover anchored to the rail button (`hidden lg:block` content) + a `lg:hidden` inline panel (the ⚡ sheet's deep links need an in-page panel on phones, where the popover anchor is display:none) — both fed by shared `renderXPicker()` fns. e2e must scope picker content to `getByRole('dialog')` (the popover) or hit strict-mode duplicates.
- **My decks has a + split button** → the site's `CreateDeckDialog`; the submit handler resolves the hero printing (dialog passes `heroCardUniqueId` only), `decksClient.createDeck`, dispatches `deckCreated` (navbar), bumps the rail count, and drills the new deck open. Throwing keeps the dialog open on failure.
- **The rail is stateful** — data launchers carry live count badges (`rail-count-{binders,wants,decks}`; binders from `binderOptions`, wants = `wantsList.cards.length` (the route has no total and ignores limit), decks = `/api/decks` filtered `!isSystemDeck && !featured` client-side — `/api/decks/basic` 404s, don't use `getUserDecksBasic`; results = `sumPersonalGames` (unit-tested): per-deck `games` from `/api/results/performance` summed ONLY for the unflagged personal deck set — a superadmin owns the Decks to Beat system decks and their games must not inflate the badge; the /recent feed clamps at 50 and can't count). The launcher whose content is open in the workspace gets `aria-current` + a left-border highlight: drills PUSH onto `workspaceStack`, so provenance = `workspaceStack[0].sourceAction` (set in `runInstant` for non-drill actionIds; `refreshDataItem` preserves it via its `...item` spread).
- `fetchToBeatHeroes` PAGINATES: `/api/decks/community` clamps limit to 50/page and the featured pool is 100+, so a single page silently drops heroes from the dropdown.
- Matchup swap-row thumbnails come from the deck card's `tableSections` via `buildSwapLookup` — the deck drill must keep its Inventory section or side-in enrichment silently degrades to name-only rows.
- **Server-side writes must refresh open tables** — CardSearchDialog adds AND successful AI write tools (`WRITE_TOOLS`) re-drill affected sources: dialog adds refresh their known target, AI writes refresh every on-screen mutable item (`collectMutationTargets`, deduped) since tool results don't say which binder/deck they hit. Fresh content swaps into matching items via uid-preserving `refreshDataItem`; a seq guard drops out-of-order responses. Without this, writes look like no-ops. The row ±/swap buttons instead update optimistically in place; a removal (− at qty 1, styled as trash) arms a 10s Undo bar that re-adds and refetches.
- **Add-card split buttons** (My binders tri-button: truncated target-binder-name segment picks via dropdown, + adds to it; My wants plus) and the deck drill's "Add card" footer button open the shared `CardSearchDialog`. Deck adds infer category from card types (hero/equipment/weapon → that slot, else maindeck) and are gated by `deckEditable` (= the deck GET's `canEdit`), so the button never shows on Decks to Beat / others' decks. The dialog closes itself in the SAME tick as `onSelectCard`, so added-card labels are recorded optimistically before the POST resolves; `flushAddDialog` folds them into one data card + one pending-context entry on close. Runners (`addSearchSelectionToBinder`/`...ToWants`) pass `forTrade` through verbatim — no `?? true` coercion.
- **Volzar is standard for all signed-in users** (2026-07) — the only gate left is signed-in vs signed-out. Logged out → inline `<AccessGate/>` with a "Sign in to chat" CTA (`/auth/login?callbackUrl=%2Fvolzar`). Do NOT restore the old signed-out `redirect()` — anonymous crawlers (Discord/Twitter embeds) must get a 200 with the OG tags from `layout.tsx`, and a 307 hides them behind the login page's metadata. Rate limits (the actual cost control): 50 msgs/user/day + 2,000/day site-wide + 30/hr burst, enforced in `/api/volzar` (policy in `lib/ai/tiers.ts`; superadmins exempt). Invariants pinned in `page.test.tsx` + `e2e/volzar-ux-fixes.spec.ts` (gitignored).
- **Cookie banner inset** — the fixed consent banner sits exactly over the composer (the shell ends where the legal footer starts). - **Prefer SQL-backed aggregate tools over inference** — "which Decks to Beat could I build?" = `compare_collection_to_decks_to_beat`; "how are my decks performing?" = `get_deck_performance`. When a suggested prompt needs decklist×binder or W/L math, add an aggregate tool — never let the model fetch lists and count. Coverage is printing-agnostic (`matchBy: 'card'`), same semantics as the deck-compare drill.
- **Comparison rows have in-row quick-add** — Missing/Partial rows carry `addQty` (needed − owned) which renders heart (wants) / folder (binder, `forTrade: false`) buttons in a tail "Add" column; handlers in VolzarChat (`quickAddRow`) write the shortage and re-drill the comparison via `compareRefresh` so the row migrates out of Missing. Actions live ON the row deliberately: the preview-rail buttons force mouse travel that hover-previews every card en route. `refreshDataItem` must copy `compareRefresh` or refreshes orphan the buttons.
- **Coverage rows are clickable** — the compare tool's MCP dispatch emits `structuredContent.coverageDecks`; `parseCoverageLines` (quick-actions) turns them into `CardLine`s with `deck-compare` drills rendered under the tool chip, so clicking a deck opens the existing You-vs-deck missing-cards comparison instantly (no AI). New interactive tool payloads should follow this pattern: structuredContent → pure parse fn (unit-tested) → existing drill/table machinery.
- **Session flags self-heal on open** — Volzar visibility (navbar item, homepage redirect, /opt "Ask Volzar") reads the login-time JWT `roles`, which goes stale when access is granted mid-session. VolzarChat calls `updateSession({})` once when the token fails `canUseVolzar` — the `{}` is REQUIRED: next-auth v5's `update()` with no args is a plain GET and never fires the jwt callback's `trigger === 'update'` DB re-read. Any client gate on Volzar access must pass ALL THREE flags to `canUseVolzar` (the /opt link shipped dropping `volzarAccess`, hiding it from manually-granted users).
- **Bridge B params are one-shot** — VolzarChat strips `?from=opt&…` via `history.replaceState` on mount so a reload can't resurrect a stale handoff.
- **Mobile shell height reserves ONLY navbar + tab bar** (7.5rem + 1px); the legal footer is a deliberate soft floor BELOW the fold — scrolling past the thread reveals it. Root layout column is min-h-**dvh**, not -screen: 100vh ≠ 100dvh on iOS and the mismatch renders as a dead band above the footer. Invariants pinned in `e2e/volzar-ux-fixes.spec.ts` (gitignored).

First-visit `country-nudge` banner (no country set) saves via `POST /api/user/country` then `router.refresh()`; "Not now" persists in localStorage `volzar-country-nudge-dismissed` — every OTHER e2e spec seeds that key or the banner shifts layout assertions.
