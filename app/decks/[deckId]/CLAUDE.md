# Deck Page HUD

See `components/CLAUDE.md` for shared UI/WCAG standards.

## Gotchas

- **`[deckId]` is the deck's `public_id`** — internal `decks.id` in a URL/API call 404s even for the owner. When testing, take ids from page links, not the DB.
- **Collector Mode ('unowned' filter) HIDES owned copies at the CARD level (2026-08, reversing the 2026-07 annotate-only call)** — owning ANY printing covers a slot (second `matchBy:'card'` comparison fetch → `cardOwnershipMap`, keyed by `card_unique_id`); only the still-missing copies stay visible, each with add-to-binder/wants buttons, and a partial playset keeps exactly its shortage. Without the card-level map (signed out / still loading) it degrades to annotate-only — hiding nothing beats hiding everything. Helpers + contract tests: `components/deck/editor/collector-mode.ts`; pinned e2e: `e2e/regression/collector-mode-hides-owned.spec.ts`.
- **Mobile opens in list view, and the default is timing-sensitive** — `resolveDefaultDeckViewMode(canEdit, isMobile)` returns `list` on narrow viewports (desktop keeps tile-for-editors / game-for-viewers). `DeckEditorListView` locks its view mode on the FIRST non-null `defaultViewMode`, and `useIsMobile` returns `false` until its mount effect reads matchMedia — so the page withholds `defaultViewMode` (`undefined`) until a `viewportResolved` flag flips, or phones lock to the desktop default.
- **Deck-tab header is ONE chip row on desktop, two on mobile** — desktop renders `[Starter Kits · Explore · Total · R/Y/B · No Pitch · Avg Cost]` on a single row (`renderPitchChips(stats, true)` inside a `hidden sm:contents` wrapper on the Kits row); mobile keeps `[Kits · Explore · Stats]` then `[Total · Red · Yellow · Blue]` (`renderPitchChips(stats, false)`, `sm:hidden`), with No Pitch / Avg Cost / zone counts in `DeckStatsPopover` (rows built by `buildDeckStatsRows`). Zone-count chips render NOWHERE on desktop by design — every view's section headers already carry the counts; don't reintroduce them. Chip labels shrink at `<sm` ("Starter Kits" → "Kits") to keep row one from wrapping — re-measure if you add a fourth chip. The hover-preview and tile-density controls are already gated to tile/game views, so list view shows only List/Tiles/Game.
- **`TYPE_KEYS` mapping** — `i→item`, `t→instant` (not swapped). Wrong order breaks Mechanologist decks (no instants → empty results).
- **`isOverlayMode` declaration order** — must be declared *before* `deckDistMap` computation or you get a TDZ `ReferenceError` at runtime.
- **`isTyping` guard** — blocks chord *entry* (`Cmd+K`) but not chord *continuation*. Once a chord is active, keypresses always route to the chord handler regardless of focused input.
- **Pitch stats must scan all three arrays** — `maindeck + inventory + equipment`. Scanning only maindeck/inventory misses cards added via the search tab (which runs `inferCategory()` and assigns equipment-typed cards to `equipment` category).
- **Card category ≠ card type** — Chord shortcuts (Cmd+9 → `maindeck`, Cmd+8 → `inventory`) bypass `inferCategory()`, so the same equipment-typed card can land in different categories depending on how it was added.
- **Turn attribution in game replay** — Some heroes (e.g. Guardians) activate weapons as `"M"` actions even on the opponent's turn. `tOppAttacks ? false` alone is wrong; when both players have `"M"` actions, fall back to parity (`idx % 2 === playerTurnIdx`). The sort also uses `turnIdx % 2 === playerTurnIdx`, not `turnIdx === playerTurnIdx`.
- **Turn log card images — tokens & removed cards** — Cards like `gold` (Gravy Bones token) are never in `deck.maindeck/equipment/hero`, so the slug lookup misses them. Cards removed from the deck since a game was played also fail. The list endpoint (`GET /api/decks/[deckId]/results`) inlines an `imageUrls` map per game, server-resolved via `cards.talishar_card_id` → first printing's `image_url`. Detail (`GET /results/[resultId]`) extends the map to turn-log cardIds, applying `normalizeTalisharId` to strip Talishar's state suffixes (`_equip`, `_ally`, `_r`, alt-art set prefixes). `DeckResultsTab` lazy-fetches detail on row expand and caches it in `detailById`.

- **Playwright vs presenter fit view** — the cookie banner intercepts clicks (pre-seed localStorage `cookieConsent` + `cookieConsentOptions` via addInitScript); fit-view tiles overlap, so click a tile's top ~30% or use dispatchEvent('click'). Specs: `e2e/deck-presenter.spec.ts` (updated 2026-08) + `e2e/regression/presenter-mobile.spec.ts`. NB fit view renders NO h2 headings — an `h2` assertion there only ever matched the cookie banner.
- **Presenter view mode is viewport-resolved (2026-08)** — `<768px` defaults to `scroll`, desktop to `fit`; `viewMode` starts `null` and resolves in a mount effect (same timing gotcha as `resolveDefaultDeckViewMode`). Fit view on mobile is opt-in and STILL clips lanes (`overflow-hidden` row, fallback branch ignores `maxPerCol`) — known, unfixed. The three floating pills go icon-only `<sm`; the view toggle hides while a card is spotlighted (it sits exactly over the spotlight's close X); spotlight arrows need `z-10` or the later-DOM panel paints over them.
- **Best-effort `import()` warms need a sync try/catch** — with a poisoned `.next` dev cache (e.g. after a syntax-error compile window), webpack's chunk loader can throw SYNCHRONOUSLY from `import()` (`encodeURIPath` on an undefined chunk name); `.catch()` on the promise doesn't cover it, and the escaped throw crash-boundaries the whole page ("Cannot read properties of undefined (reading 'split')", navbar looks signed-out because React froze pre-session). Presenter's `warmHoloCard` effect hit this; recovery for the flake itself = pkill next, `rm -rf .next`, restart.
- **QuickAddCardDialog = shared /opt search machinery + baked legality (2026-08)** — `optSearchReducer` + `buildFilterFacets` (excluded facets + `hideHeroAges`) + `useCardSearch`; filters via `buildDeckAddFilters` (`lib/search/deck-add-filters`), legality from `resolveHeroFilter` (`lib/deck/resolve-hero-filter`). Grouped results (`limit` counts CARDS; printings lazy-load on select via `fetchPrintingsForCard`); Strict/Fuzzy pill = `useCardSearch` `matchMode` ('strict'|'broad'). Swap mode (curation `initialSearch`) is a deliberately separate minimal branch on the old exact-name GET path — do NOT route it through the reducer. Hero-pool preload/pool-browse removed; `/api/cards/by-hero` has no in-app consumers.
- **Dialog Escape = two document-capture listeners that BOTH fire per press** (own capture handler + Radix's) — same-node capture listeners ignore `stopPropagation`, and it's safe only because both act on the same pre-render state (idempotent). Any "Escape claims this" rule (e.g. the open-facet-popover tier 0) must be guarded in BOTH paths or Escape closes the dialog underneath.
- **Playwright vs ArtChip buttons** — the accessible name duplicates the label (img alt + visible text → "Attack Attack"), so `getByRole('button', { name: /^Attack$/ })` never matches; select with `button[title="Attack"]`. Facet trigger names grow a count badge ("Type 1") — anchor with `/^Type\b/`, not `/^Type$/`.

- **Per-card deck tags removed (2026-07-30)** — never persisted (no `deck_cards` column, PATCH route never existed). Deck-LEVEL `decks.tags` is real and untouched. Per-card context belongs in deck notes (`cardNotes`), which MCP coaching reads.
- **Playmat ownership overlay** — maps the inventory-comparison DTO via `lib/deck/ownership-map.ts`. The for-trade toggle + binder links are gated on `forTrade`/`binderSlugs` field presence: the endpoint doesn't return them yet, and absence means "unknown", not false/empty. Enrich the service before un-gating.
- **Pimp My Deck (`/decks/[deckId]/upgrade`)** — for each deck card, the blingier ENGLISH printings the VIEWER doesn't own anywhere in their collection (strictly above their best owned copy's bling; owning nothing sets the bar at "plain base"). Engine is pure (`lib/deck/pimp-upgrades.ts`: score = foil ladder NF<RF<CF<GF + marvel/promo rarity + EA/alt-art + alpha/first edition); route `GET /api/decks/[deckId]/pimp` composes findByPublicId + `searchPrintings({cardUniqueIds, languages:['en']})` + `getOwnedCountsByPrintingId`. NB the search wire shape's proper-cased name field is `name` (PrintingDTO has NO `display_name`). Entry: the whole-banner-art button in the display toolbar next to Webcam on md+ (small chip on the stats row < md; whole picture by owner call — no plain-text label), signed-in only, all viewers — it's viewer-collection-scoped, distinct from the owned-alternatives `upgrade-printings` swap dialog). Pinned in `e2e/pimp-my-deck.spec.ts`.
- **Export image (More → "Export image") renders CLIENT-SIDE on a canvas** — `lib/deck/deck-image.ts` (pure model + layout, node-tested) → `lib/deck/deck-image-render.ts` (browser canvas, share/download) → `DeckExportImageDialog`. No server route: card art is drawn straight from stored `image_url`s, which works only because Cloudflare Images sends `access-control-allow-origin: *` on the `public` variant (tainted canvas = `toBlob` throws). Native **Share** shows only where `navigator.canShare({files})` is true (phones; headless Chromium says no, so e2e covers Download only). The page's own mobile tab pill is `z-50` like the dialog and later in the DOM, so it's hidden while the dialog is open. Pinned in `e2e/regression/deck-export-image.spec.ts`; `e2e/auth.json` expires (~1 month) — a helper stuck on "Sign In Required" means refresh it, not a code bug.
- **Deck Tools trigger has two homes** — on the xl deck tab it is the right rail's first row and the floating pill is `xl:hidden`; everywhere else it floats bottom-right (sm+) or bottom-center (phones). A fixed pill over the tile grid or the in-flow rail hides content at some scroll position, so don't re-float it on desktop. The rail itself is `position:fixed` once pinned and clamps its top to the content row's bottom so it never paints over the footer.
- **Tiles are tab stops and actions reveal on `group-focus-within`** — an 80-card deck is ~480 stops (tile + up to 5 buttons); roving tabindex is parked, not forgotten.
- **e2e: `createSeededDeck` returns when the save button hides, which is optimistic** — navigate to the deck and assert the tile count before closing the fixture page, or the seed can be lost. A fixed-element overlap test must sweep scroll positions; a single position passed twice on the buggy pill.
- **Two deck hooks, don't add useDeckPage consumers** — `useDeckEditor` powers the main deck page; `useDeckPage` (older, larger) powers ONLY the analyze page + PlaymatView/MobileDeckLayout/DeckPageDialogs typed against it. The main page already migrated off it; unification is parked, so new work should build on `useDeckEditor`.

## Custom Events

| Event | Direction | Purpose |
|---|---|---|
| `deck-highlight-filter` | dispatch + listen | Filter cards by stat/value; tracked in `activeHighlights` state |
| `deck-highlight-clear` | dispatch + listen | Clear all highlights (double-Escape) |
| `deck-tile-size` | dispatch | Request tile size change (`{ direction: 'smaller' \| 'larger' }`) |
| `deck-tile-size-update` | listen | Sync tile size label from `DeckEditorListView` |
